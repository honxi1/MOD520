第 1 章 · 环境搭建

在开始写代码之前，先把开发环境准备好。本章会带你把工具链装齐，并跑通一个「空项目」的构建，为后续开发打好基础。

本章目录
  1. 需要准备的工具
  2. 安装与验证
  3. 配置 IDE
  4. 验证环境是否正常
  5. 常见问题

1. 需要准备的工具

MOD 开发本质上是一个软件工程过程，你至少需要下面几样东西：

工具作用备注
JDK运行和编译 Java 代码按你使用的框架要求选择 8 / 17 / 21 版本
构建工具下载依赖、编译、打包Gradle 或 Maven，二选一
IDE写代码、调试IntelliJ IDEA 社区版即可，免费够用
目标游戏本体运行与测试准备一个用于测试的干净安装目录
提示：所有工具请从官网下载，避免使用来源不明的整合包。

2. 安装与验证

2.1 安装 JDK

打开命令行，输入下面的命令检查是否已安装：

java -version

如果输出版本号，说明已安装；否则请到官网下载对应版本的 JDK 并安装，安装完成后重新打开命令行再验证一次。

2.2 配置 JAVA_HOME

确保环境变量正确指向 JDK 的安装目录，而不是 JRE：

echo %JAVA_HOME%

如果为空，请按你的操作系统把 JAVA_HOME 设置为 JDK 根目录，并把 %JAVA_HOME%\bin 加入 PATH。

2.3 验证构建工具

gradle -version

输出版本信息即正常。如果未安装，可以直接在项目里使用 gradlew 包装器，它会自动下载对应版本的 Gradle。

3. 配置 IDE

  • 安装 IntelliJ IDEA 社区版。
  • 插件市场安装你所用 MOD 框架的官方插件（如有），例如 Minecraft 模组开发可安装 Minecraft Development。
  • 首次打开项目时，选择「从已有源码导入」，让 IDE 识别 build.gradle。
  • 确保 IDE 使用我们刚配置好的 JDK：File → Project Structure → SDK。

4. 验证环境是否正常

新建一个空项目目录，执行构建命令，确认依赖能正常下载、项目能编译：

gradlew build
注意：首次构建会下载大量依赖，速度取决于网络。如果你处于网络受限环境，可配置镜像源加速。

5. 常见问题

  • 提示 Unable to locate a Java Runtime：说明没有安装 JDK 或 JAVA_HOME 配置错误，回到第 2 节检查。
  • 依赖下载失败 / 超时：检查网络，或为构建工具配置国内镜像源。
  • IDE 识别不了项目：删除 .idea、.gradle 目录后重新导入。
练习题：创建一个空项目并成功跑通 gradlew build，记住「构建成功」的界面长什么样——下一章我们会让这个空项目长出一个真正的 MOD。
