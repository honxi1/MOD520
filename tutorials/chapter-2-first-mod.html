第 2 章 · 第一个 MOD

环境就绪之后，本章我们从项目骨架开始，编写一个最简 MOD 并让它被游戏加载，理解「入口类」和「加载流程」这两个核心概念。

本章目录
  1. 创建项目骨架
  2. 声明 MOD 元信息
  3. 编写主类
  4. 运行并验证
  5. 常见问题

1. 创建项目骨架

建议使用你所用框架的「官方模板 / MDK」生成项目，模板会帮你把构建脚本、目录结构一次配好。大致结构如下：

my-mod/
├── build.gradle          # 构建配置，声明依赖
├── gradle.properties     # 框架版本、项目版本等
├── src/main/
│   ├── java/             # Java 源码
│   │   └── com/example/mymod/
│   └── resources/        # 元信息、资源、语言文件
└── gradlew               # 构建包装器

目录名字典序可自定义，但 src/main/java 与 src/main/resources 是构建工具的约定，不要改。

2. 声明 MOD 元信息

在 resources 下放置框架要求的元信息文件，例如：

{
  "modId": "mymod",
  "name": "My First Mod",
  "version": "1.0.0",
  "entrypoint": "com.example.mymod.MyMod"
}

三个字段最重要：modId（全局唯一，只能用小写字母数字和下划线）、version（版本号，遵循语义化版本）、entrypoint（入口类的完整类名）。

注意：modId 一旦确定就不要再改。它是存档、网络同步的标识，改名会让旧存档失效。

3. 编写主类

入口类是游戏加载 MOD 时第一个执行的代码。一个最简实现长这样：

package com.example.mymod;

public class MyMod {
    public static final String MOD_ID = "mymod";

    public void onInitialize() {
        System.out.println("Hello from " + MOD_ID + "!");
    }
}

要点：

  • MOD_ID 常量与元信息里的 modId 保持一致，后续注册都用它。
  • onInitialize() 是框架约定的初始化入口，游戏启动时调用。
  • 不要在构造函数里做注册，初始化动作统一放在入口方法里，保证顺序可控。

4. 运行并验证

执行运行任务启动带 MOD 的游戏：

gradlew runClient

启动后在日志中搜索你的输出，看到以下内容即成功：

[main/INFO]: Hello from mymod!
练习：把输出改成「Hello from mymod, version 1.0.0」，并再启动一次验证改动生效。习惯「改代码 → 跑一遍 → 看日志」的循环，这就是开发节奏。

5. 常见问题

  • 启动后日志里没有我的输出：确认元信息文件里的 entrypoint 类名与包名拼写完全一致。
  • 提示 modId 冲突：你的 modId 与已安装的其他 MOD 重复，换成更独特的名字。
  • 构建报错但看不到原因：加 --stacktrace 重新构建，把完整错误贴出来再排查。
