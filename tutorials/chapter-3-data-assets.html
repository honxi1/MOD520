第 3 章 · 数据与资源

一个可玩的 MOD 不只是代码，还需要配置、贴图、模型和文本。本章教你如何组织「数据与资源」，以及如何把它们挂到代码上。

本章目录
  1. 配置文件
  2. 资源目录结构
  3. 本地化（多语言）
  4. 把资源挂到代码上

1. 配置文件

把「数值」和「行为开关」从代码里抽出来，放进配置文件，方便玩家调整而不需要重新编译。常见的做法：

# config/mymod.toml
[general]
enable_effect = true
max_level = 5
damage_multiplier = 1.5

配置的读取时机放在初始化阶段，读取失败时要给默认值并打日志，避免玩家改错导致崩溃：

int maxLevel = config.getInt("general.max_level", 5);

2. 资源目录结构

资源通常放在 resources 下的固定命名空间中：

resources/
├── assets/mymod/
│   ├── textures/block/my_block.png
│   ├── models/block/my_block.json
│   └── sounds/my_sound.ogg
└── data/mymod/
    └── loot_table/...

命名空间（这里的 mymod）与 modId 对应。资源路径约定为 assets/<namespace>/<类型>/<路径>，遵守约定才能被正确加载。

图片推荐 16×16、32×32 等 2 的幂尺寸，格式用 PNG。命名全部小写，用下划线分词。

3. 本地化（多语言）

玩家界面上的文字不要写死在代码里，而是放到语言文件，让不同语言的玩家看到对应翻译：

// assets/mymod/lang/zh_cn.json
{
  "item.mymod.my_item": "我的物品"
}

// assets/mymod/lang/en_us.json
{
  "item.mymod.my_item": "My Item"
}

代码里用翻译键引用：

langKey = "item.mymod.my_item"

4. 把资源挂到代码上

在入口或注册阶段，把资源 ID 与代码对象绑定。大多数框架都提供类似的注册 API：

registerItem(
    new ResourceLocation(MOD_ID, "my_item"),  // 资源 ID
    new MyItem()
);

这里的 ResourceLocation（资源 ID）由 命名空间:路径 组成，它同时决定了语言键、纹理路径等默认值，所以命名要规范。

5. 常见问题

  • 贴图显示为紫黑格：贴图路径与资源 ID 不匹配，检查命名空间和文件放置位置。
  • 语言文件不生效：确认文件名（如 zh_cn）与编码（UTF-8）正确。
  • 配置改动无效：确认读取时机在改动之后，或配置被缓存，尝试重启。
练习：添加一个自定义物品，配上 16×16 贴图和中文/英文名称，然后在游戏中拿起来看看。
